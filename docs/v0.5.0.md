# GitCanvas 0.5.0 user guide

GitCanvas 0.5.0 makes large repositories easier to navigate by bringing branches, tags,
linked worktrees and update status into a more capable sidebar and Preferences panel.

## Find and organize references

The **Branches and tags** section lists local branches, remote branches and tags. Use the
search field to narrow the list by name. Slash-separated names are grouped into folders;
select a folder or group heading to collapse or expand it. The header menu provides bulk
collapse and expand actions, and the help control explains the icons and their effects.

Each reference has an eye control. Turn it off to exclude that reference from the history
graph; turn it on to include it again. Group and folder controls apply the same change to
their descendants. **Include HEAD** is independent, so the checked-out commit can remain in
the graph even when its branch is hidden. **Show all** restores the full reference set, and
the undo action reverses the most recent filter change.

These settings are scoped to the current worktree. GitCanvas remembers visible references,
the search text and which groups or folders are folded when you switch project tabs or
restart the app. Branch colors and the visual main branch are shared across linked worktrees
that GitCanvas has validated as part of the same repository.

Filtering changes which history the graph walks; it does not delete commits or change Git
references. If you select a commit that is outside the current filter, its details remain
available and GitCanvas offers an action to reveal it in the history.

## Browse linked worktrees

The **Linked worktrees** section lists working directories attached to the repository, with
their checked-out branch and availability. Use the refresh button after creating or removing
a worktree outside GitCanvas. Select an available row to open it in its project tab; if that
worktree is already open, GitCanvas reuses its tab. A **Worktree** badge on a branch indicates
that the branch is checked out elsewhere. Hover the badge to see the worktree path.

GitCanvas only opens worktrees reported by Git for the current repository. It does not create,
remove or repair worktrees from this panel.

## Check and install updates

Open **Preferences → Updates** to see the installed version and choose **Check for updates**.
When a newer signed release is available, GitCanvas shows its version and offers **Download
and install**. The app verifies the update signature before installation and restarts when
installation completes.

If GitHub Releases cannot be reached, Preferences shows that the check failed and offers a
retry. That message does not indicate that the installed version is current. If no newer
release exists, GitCanvas confirms that the displayed installed version is up to date.

The first release containing the updater must be installed manually. Later signed releases
can be installed from Preferences.

## Version 0.5.0 highlights

- Searchable, hierarchical branch and tag explorer with per-reference visibility controls.
- Per-worktree persistence for filters, search text and expanded or collapsed tree sections.
- Linked worktree inventory and navigation between project tabs.
- Signed in-app updates with an explicit installed-version display.
- Lazy loading for the GitHub repository picker and file diff viewer.
