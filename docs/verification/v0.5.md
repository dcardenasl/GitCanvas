## E2E nativo macOS

Los ocho specs (`collapse`, `commit-tree`, `critical-path`, `graph-performance`, `graph`,
`local-changes`, `v05-filters-worktrees` y `workspace`) pasaron contra el binario nativo
con WebKit, ejecutando `npm run test:e2e` en macOS desbloqueado. El spec `workspace`
pasó sus tres recorridos; la ejecución anterior con la sesión bloqueada no cuenta como
resultado funcional y quedó reemplazada por esta repetición completa.
El spec v0.5 contiene cuatro recorridos. El nuevo fixture usa repositorios temporales de propiedad de la suite: contiene
un merge, tag anotado, worktree enlazado con rama ocupada y cambios locales. Comprueba
el alcance real del historial, el aviso de detalle excluido, Mostrar todo y localizar,
la visibilidad de cambios locales, la apertura del worktree ocupado, la reutilización
de la pestaña y el indicador temporal que conserva el diff. Las pruebas existentes de
gráficos también cubren la persistencia en esquema 3. El cuarto recorrido verifica
traducciones y controles de referencias/worktrees en inglés y español, tema claro y
oscuro y ventana de 940×600 sin desbordamiento horizontal; restaura las preferencias
originales al finalizar. También se inspeccionó visualmente el binario v0.5 aislado en
macOS: panel, inventario y jerarquía de referencias en claro y oscuro; los controles
visibles y etiquetas accesibles se comprobaron en ambos idiomas. La prueba E2E de
940×600 pasa con ancho interior 940 y sin overflow.

## Linux arm64 local

En un contenedor Debian 12 arm64 con WebKitGTK y Xvfb pasaron `npm ci`, `npm run
typecheck`, `npm run lint`, la suite Vitest (830 pruebas), formato Rust, Clippy estricto,
`cargo test --workspace --all-features` y `npm run build`. La ejecución se detuvo al
compilar el binario release para E2E: el filesystem overlay de Docker se volvió de solo
lectura durante la compilación de OpenSSL (`openssl-sys`, error de escritura de archivos
`.d.tmp`). Por tanto esto aporta evidencia Linux de compilación y tests, pero no evidencia
de E2E nativo Linux. No se limpió el Docker global ni se borraron volúmenes ajenos.
