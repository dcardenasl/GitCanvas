# v0.4 — Verificación y gates de release pendientes

Fecha: 2026-10-19. Entorno local: macOS 26.3, Apple M1 Pro (arm64), Node 22.22.3. Implementación en `dev`; la versión de la aplicación sigue en 0.3.1 hasta la release.

## Evidencia local

- Frontend: Node 22, todas las configuraciones de tipos, ESLint y comprobación de formato.
- Frontend: 807 pruebas en 84 archivos; 95,50 % de sentencias, 96,87 % de líneas, 88,68 % de
  ramas y 95,31 % de funciones. Pasan todos los umbrales globales y por módulo.
- Rust: 220 pruebas con todas las features; Clippy estricto; los bindings generados no
  cambian al regenerarlos.
- Auditoría de dependencias de producción: npm informa cero vulnerabilidades. `cargo deny`
  pasa; `cargo audit` pasa con las ocho advertencias transitivas ya permitidas. No se
  cambió ninguna política.
- El bundle de producción de macOS se construyó y su firma ad hoc se verificó con
  `codesign` estricto y profundo. Las dependencias de producción por defecto excluyen
  WebDriver. Después se reconstruyó el código final con el perfil E2E optimizado para el
  último recorrido nativo.
- Arnés nativo: WebdriverIO/Tauri, WebKit real de macOS, repositorios desechables aislados,
  webview privado y datos Rust temporales. El plugin de navegador no está disponible; se usa
  el flujo E2E nativo existente en lugar de reemplazar el IPC por simulaciones de navegador.
- Flujos nativos nuevos: elegir color y principal sin checkout, almacén con esquema 2,
  cerrar y reabrir, paleta clara en inglés a 940×600, historial de 10.000 commits con
  doce trayectorias vivas.
- Layout puro: cada división de los fixtures, DAG generados, 1.200 commits en páginas de 500,
  principal tardía, merges repetidos hacia un extremo nombrado futuro, octopus y uniones
  reales de nodos.
- Estado: una edición más nueva entre el render y el efecto prevalece; los callbacks
  retenidos nombran su worktree original; las generaciones de raíz obsoletas se liberan;
  las páginas de historial sin cambios son reutilizables.
- Migración y recuperación: la versión 1 conserva pestañas, navegación y biblioteca; las
  preferencias de proyectos cerrados hacen el recorrido de ida y vuelta; se validan la
  secuencia de ediciones y las identidades de referencias.
- Detector mecánico de Impeccable: sin hallazgos en las superficies modificadas.

## Método de rendimiento

`GITCANVAS_E2E_FIXTURE_KIND=graph-performance` construye 10.000 commits lineales y once
extremos de ramas desde una base común más antigua usando `git fast-import`, dentro del
fixture temporal propio. La prueba nativa selecciona `main`, desplaza durante 180
callbacks de `requestAnimationFrame`, cuenta nodos y conexiones montados y escribe una
medición JSON temporal. El tiempo se informa, no se convierte en una aserción de CI
dependiente del hardware.

Primera ejecución en macOS arm64 a 1280×800: 60,24 fps durante 2.988 ms; intervalo máximo
entre fotogramas de 19 ms; 44 nodos montados y 1.056 trazos de media fila con color. Logs
del backend: instantánea de referencias 5 ms, primera página de 500 commits 46 ms. Es
latencia de datos del backend, no una afirmación sobre el arranque completo del proceso ni
sobre el primer pintado de extremo a extremo. Segunda medición nativa tras la corrección de
render: 60,54 fps durante 2.973 ms, intervalo máximo de 20 ms, 44 nodos y 1.056 trazos;
instantánea 12 ms y primera página de datos 56 ms. Medición final con el binario
reconstruido: 60,28 fps durante 2.986 ms, intervalo máximo de 18 ms, 44 nodos montados y
1.056 trazos de media fila con color. Son resultados locales, no garantías para cualquier
equipo. Observaciones finales del backend: instantánea 6 ms y primera página de datos 45 ms.

La primera inspección de capturas identificó huecos causados por contornos por segmento
que cubrían los extremos vecinos. Ahora los contornos preceden a cada conexión con color;
una prueba de regresión comprueba las capas de dibujo y las capturas se repiten tras
reconstruir.

Las capturas e informes temporales quedan fuera del repositorio. Las comprobaciones de
salud del renderizador verifican contenido significativo, el título del proyecto GitCanvas,
ausencia de overlay de Vite y ningún error o advertencia capturado del renderizador en cada
sesión. Las nuevas aserciones de selectores y título se corrigieron contra el DOM nativo
real. El sondeo de cambios locales ahora lee una vista fresca del DOM de forma atómica para
evitar manejadores de elementos de WebDriver obsoletos durante el refresco; la captura de
errores sigue activa.

El plugin de WDIO emite una advertencia de limpieza tras las sesiones; las aserciones pasan
y la aplicación no usa ningún almacén simulado. Esta advertencia no se cuenta como fallo del
producto ni se suprime en silencio.

## Recorrido final con el binario reconstruido

- Siete archivos de especificaciones nativas, dieciséis pruebas, todas aprobadas. La
  captura de salud del renderizador siguió activa.
- Preferencias del gráfico: español/oscuro e inglés/claro a 940×600, edición de color con

- Evidencia temporal: `gitcanvas-v04-graph-dark.png`, `gitcanvas-v04-palette-light-en.png`,
  `gitcanvas-v04-large-graph.png` y `gitcanvas-v04-performance.json` en el directorio
  temporal del sistema operativo.

## Gates externos y manuales aún abiertos

- Ejecutar la revisión actual de `dev` en E2E nativo de Linux y Windows, builds y la matriz
  de calidad cuando se autorice la ejecución remota o la publicación. Los resultados
  anteriores de v0.3.1 son históricos.
- Validar con un lector de pantalla real; las comprobaciones automáticas de etiquetas y foco
  no equivalen a esa prueba.
- Conciliar el menú nativo manual original de macOS y los demás puntos de la lista manual de
  WS-17 por plataforma que no tienen evidencia humana; publicar v0.3 no prueba cada caso
  manual.
- La latencia completa desde el arranque del proceso hasta la primera página visible no se
  mide con las duraciones de las operaciones de Rust. Se mantiene el objetivo de 300 ms para
  la primera página sin afirmar un benchmark de arranque completo.
- Esta implementación no realiza push, pull request, merge, etiqueta ni publicación.
